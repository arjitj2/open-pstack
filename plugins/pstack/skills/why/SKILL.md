# Why

Answer from the record: the commits and PR discussions that introduced the target and each substantive later change. Read code to locate the target, not to prove its authors' intent. State your interpretation if the question is ambiguous.

Resolve both investigator and synthesizer assignments from the exact `why investigators, synthesizer` row through [provider dispatch](../poteto-mode/references/provider-dispatch.md). Pass the full row header `why investigators, synthesizer` to the helper for both assignments; bare `synthesizer` is ambiguous with Reflect. Keep its frozen sheet, saved recovery, worker contracts, spending gates, verified completion, and named dropouts. The permitted legacy unconfigured default is `inherit-parent`. Why requires the parent's live MCP surface: use native `inherit-parent` or `auto` lanes with their assigned tools and a no-write posture. A tool mode that strips MCPs or an external worker without them is not equivalent. On Codex, apply [the tool mapping](../poteto-mode/references/codex-tools.md).

1. Establish the code anchor: paths, line ranges, symbols, introduction, later changes, PRs, and linked issues. Follow history through renames. Read substantive PR bodies and discussions, rather than relying on the latest blame or a search preview. Report unavailable history or account access as gaps.
2. Discover tools from the active parent's live catalog. Dispatch one source-control investigator through the saved investigator role. Add targeted investigators when linked records, a thin trail, contradictions, defensive behavior, or the question call for them. Consider issue trackers, long-form documents, team chat, infrastructure observability, error tracking, and product analytics. Give each investigator one source, the anchor, and the question. Follow cross-source leads through the appropriate source assignment. A broad history request needs broad coverage; a narrow question does not require every category to run.
3. Each investigator reads full records and returns precise citations, relevant author statements, queries and scope, null results, contradictions, and unresolved leads. Record unsearched categories with their reasons. Distinguish unavailable access from a search that returned nothing. Do not infer that an unavailable source has no relevant evidence.
4. After every investigator has a verified terminal result or named dropout, dispatch one native synthesizer through the saved synthesizer role. Give it the question, anchor, complete findings, and coverage limits. It checks disputed or uncertain citations through the available tools and answers only what the record supports. Verify its terminal result before presenting it; do not replace a denied lane with unassigned parent work.

The answer separates Direct author statements, Supported conclusions from converging records, Inferred interpretations, Speculative alternatives, and Unknown gaps. Cite each factual historical claim. Mark inferences and show the evidence that supports them. Keep contradictions visible, test the user's proposed explanation independently, and never retrofit a plausible intent from code. State what the record does not answer. Include Sources Consulted with actual searches, null results, skipped categories and reasons, and named dropouts. If the answer precedes a change, add Preserve / Change / Avoid / Risk constraints from the lineage. Keep the synthesizer's confidence language intact when presenting it.
