# Selected-provider setup behavioral checks

Run the installed candidate through `pstack:setup-pstack` in both Claude Code and Codex, using an isolated test home and authenticated test accounts. Do not modify a personal model sheet. Record candidate revision, installed plugin version, parent, setup conversation, launched probes, and before/after sheet and integration bytes. These cases test the skill's actual decisions; Markdown assertions alone do not establish that they pass.

1. **Missing unused provider.** Start without a sheet and with Grok unavailable. Explicitly replace Grok's single-role assignments with `inherit-parent` and remove Grok from each panel. Keep other assignments. Expect no Grok effort question, authentication check, probe, or smoke lane. Selected families must pass; all 15 role rows remain, panels are nonempty, and Why/Reflect remain native. Confirm, then verify the sheet and parent integration agree.
2. **Selected-provider failure and recovery.** Keep Grok selected while its CLI is unavailable. Expect the failing pair and affected roles, no writes, and explicit repair/remap/cancel choices. Choose the same Grok replacements as case 1. Expect revalidation and only final assigned pairs in the saved configuration; do not accept silent removal or fallback. Repeat with an existing customized sheet and verify both targets remain byte-identical until confirmation.
3. **Native-only configuration.** Select `inherit-parent` for every role, including two independent entries in `architect runners` and one entry in every other panel. Expect no provider CLI checks or family effort questions, but require a real inherited native-agent marker probe before confirmation and writes. Disable native delegation first and verify both targets stay unchanged; the parent answering the marker itself must not pass. Re-enable delegation and retry, then verify a native panel and separate native judge, with a reduced-diversity notice. Why/Reflect stay native. No placeholder model descriptors may be inserted to retain unused family efforts.
4. **Preserved customization.** Start with a complete customized sheet using only two families, including reordered panel entries and aliases. Change one family's effort. Expect one probe per assigned pair, every occurrence of the changed family updated, and unchanged role families, aliases, and lane order. Repeat with no changes and require byte-identical output.
5. **A newly selected family fails.** Add a family during confirmation, after earlier probes passed. Expect setup to return to assignment validation and probe that family before writing. Reject an invalid effort and a request that empties a panel; preserve the current targets until corrected.
6. **Architect minimum with one available provider.** Request `architect runners: inherit-parent` or remove one entry from a two-entry architect panel. Expect setup to stop before probing or writing and ask for a second entry. Explicitly choose `inherit-parent, inherit-parent`; expect acceptance without adding or checking an external provider. Preserve both entries in the sheet, report reduced diversity, and verify Architect dispatches two independent candidates and requires structurally distinct designs before synthesis. A one-entry Arena runner panel remains valid.
7. **Write failure.** After probes and confirmation, make one target unwritable in the test home. Expect rollback of both targets to their snapshots, including absence when a file did not exist. Setup must report failure rather than completion.

A missing selected provider is an intentional failure in case 2, not a reason to skip the case. Successful native and external probes must be real one-turn runs. Record any unavailable live harness or fixture as unverified.

8. **Opt-in models and Sonnet migration.** Assign Sonnet and one of Astra/Luna/Terra to named roles at explicit efforts. Preserve unrelated customized lanes and aliases; require only assigned pairs to be probed. Repeat for the remaining Codex families. Load a numeric versioned Sonnet descriptor and verify native dispatch or external argv uses the rolling alias before writes, then confirmation persists it. A failed new-family probe must leave both targets unchanged. First-run defaults must still contain only Fable/Sol/Grok/Opus.
9. **Capacity-bounded native waves.** Select more distinct native descriptors than available slots, including an inherited alias. Record available capacity and every launch, completion, drain, and release. No wave may exceed available slots; completed handles must release capacity before another wave. Repeat when capacity cannot be observed and expect sequential native execution. External lanes must still start concurrently. All candidates must complete before a separate judge launches; never substitute a route, cancel, or time out work to make room.

10. **Subscription discovery and recommendation.** Start with observable CLI/auth/model facts already discoverable and leave subscription, capacity, and spend answers unknown until asked. Expect setup to present observed facts separately from user-reported ones, to ask only the missing facts (funding, capacity expectation, `apiSpend`, plan label), to reuse facts already persisted in `# access` lines, and to recommend a task-fit mix with explicit ordered fallbacks while preserving customized assignments by default. Unknown answers must persist as `unknown`, never as included or unlimited. Rejecting the recommendation must keep the existing map intact.
11. **Saved fallback chain.** Confirm a sheet with `primary -> fallback` on one seat. Under a controlled or real `usage-exhausted` result on the primary, expect the parent to launch exactly the saved fallback descriptor with fresh output/receipt paths and to report both descriptors and actual provider diversity. Before replacement, require a visible notice naming the failed descriptor, observed cause, and exact approved backup; inspection notices must precede inspection and continuation notices must wait for a clear verdict. No failure-time permission question is allowed; a generic failure (auth, model, timeout, cancellation, malformed output, generic 429) must remain a dropout on a quota-only sheet. A legacy single-descriptor sheet authorizes no fallback. A proved-not-started writer can advance directly. Otherwise expect autonomous `inspect -> clear -> next approved attempt` with no permission prompt, preservation of partial work in a reviewed continuation snapshot, and a fresh writer worktree. An unsafe inspection must stop only that lane; retain the failed worktree and receipt. A sheet carrying `# fallback: {"on":[...]}` may additionally advance on its declared outcomes — `route-unavailable`, `terminal-failure`, `deadline-exceeded` — through the same saved chain, inspected writers, and receipt normalization boundary; sheets without the line stay quota-only.
12. **API-spend policy.** With an ambient API credential present (for example `CURSOR_API_KEY`), expect setup to ask for explicit API permission before any probe that could spend money, to record the answer in `# access` (`apiSpend: "approved"` or `"deny"`), and to run the corresponding probe with `--api-spend`. A denied route must produce a `billing-policy-blocked` receipt before execution; legacy configurations without the flag keep their prior behavior. Setup must never read or print credential values, never redeem credits or enable billing, and never claim zero-charge guarantees — provider-managed overage remains possible under OAuth.
